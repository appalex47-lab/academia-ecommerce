FASE 4 — FLUJO DE APRENDIZAJE Y PROGRESIÓN COGNITIVA

Objetivo
-------
Se añadió una capa contextual de progresión cognitiva sobre la arquitectura de Fases 1–3.
La aplicación ahora puede representar y comunicar el recorrido:
Comprender → Calcular → Interpretar → Diagnosticar → Formular hipótesis → Recomendar → Aplicar.

Principios de implementación
----------------------------
- Se extendió el modelo existente; no se creó un segundo motor de ejercicios.
- Se reutilizan cognitiveLevel, type, concepts y el estado de ejercicios de Fase 2.
- CASE de Fase 1 se presenta en la ruta visual como Aplicar; no se cambia el metadata existente.
- La progresión no es mastery ni scoring.
- Practicado significa que existe al menos un intento en un ejercicio de ese nivel.
- Completado significa que el ejercicio correspondiente fue resuelto correctamente.
- Ninguno de esos estados se presenta como dominio del concepto.
- No se agregaron bloqueos nuevos de navegación.
- No se creó una segunda persistencia.

Representación por lección
--------------------------
L1: Calcular.
L2: Calcular → Interpretar.
L3: Interpretar.
L4: Interpretar.
L5: Diagnosticar → Formular hipótesis (la hipótesis ya forma parte del contenido de la lección).
L6: Diagnosticar → Formular hipótesis (la hipótesis ya forma parte del contenido de la lección).
L7: Interpretar como refuerzo del análisis de clientes.
L8: Diagnosticar → Formular hipótesis → Recomendar → Aplicar, integrando el contenido ya existente del proyecto.
Cierre: mapa completo.

UX integrada
------------
Cada lección recibe dinámicamente un bloque contextual “Ruta de aprendizaje” con:
- nivel que se está practicando;
- recorrido cognitivo de la lección;
- estados visuales de practicado/completado;
- explicación breve de qué sigue.

El bloque se inserta dentro de la lección existente y no crea una pantalla nueva.

Accesibilidad
-------------
- La ruta utiliza estructura semántica de sección.
- La lista de etapas utiliza role=list/listitem.
- El contenido es texto y no depende únicamente del color.
- Se mantiene el patrón aria-live ya utilizado por Fases 2 y 3 para feedback dinámico.

Integración
-----------
Fase 1: reutiliza la taxonomía y metadata pedagógica existentes.
Fase 2: deriva practicado/completado desde attempts/completed/solvedCorrectly y conserva localStorage.
Fase 3: no sustituye feedback, diagnóstico ni “PIENSA COMO ANALISTA”.

Limitaciones deliberadas
-------------------------
No se implementó:
- mastery;
- scoring;
- ranking;
- gamificación;
- repaso espaciado;
- recomendaciones adaptativas;
- IA/LLM/NLP;
- dashboard completo;
- laboratorio completo de casos;
- evaluación final;
- adaptación automática de dificultad;
- segunda base de persistencia;
- segundo motor de ejercicios.

Validación manual
-----------------
Se intentó una validación en navegador Chromium headless para comprobar el DOM integrado.
Si el navegador del entorno no devuelve el DOM dentro del tiempo disponible, esa prueba se
considera pendiente y no se declara aprobada. Las pruebas automatizadas de integración y
regresión sí deben pasar antes de entregar la fase.
