FASE 11 — PERSISTENCIA AVANZADA Y CONTINUIDAD DEL APRENDIZAJE

ESTADO
Implementado → integrado → probado → documentado → detenido.

AUDITORÍA INICIAL
- La aplicación ya utilizaba una única clave localStorage: cursoAnalista.fase2.progress.v1.
- El payload se guardaba como JSON con version: 1.
- Se persistían lecciones, ejercicios, casos y repaso; la evidencia de conceptos se reconstruía.
- No existía schemaVersion explícito ni migración formal.
- currentIndex se persistía, pero la vista activa (curso/dashboard/repaso/casos) no.
- No existían exportación/importación ni reinicio explícito.
- saveLearningState podía serializar/escribir repetidamente.

FUENTE DE VERDAD
Primarios: lessonStatus, exerciseLearningState, caseLearningState, reviewLearningState, currentIndex y navigation.activeActivityId/activeView.
Derivados: conceptEvidence y contenido del dashboard, reconstruidos desde la evidencia primaria.
No se crea una segunda base de datos ni una segunda clave localStorage.

ESQUEMA
schemaVersion: 2. Se conserva la clave de almacenamiento existente para compatibilidad.

MIGRACIÓN
Los datos version 1/version sin schemaVersion se migran a schemaVersion 2 conservando progreso, ejercicios, casos y repaso. Datos de una versión futura o estructuras inválidas no se sobrescriben automáticamente.

RECUPERACIÓN
- JSON corrupto: defaults seguros + aviso visible; se bloquean escrituras automáticas para evitar sobrescribir el dato original.
- Estructura inválida: misma protección.
- Datos incompletos por campos individuales: sanitización con defaults seguros.
- Versión futura: no se sobrescribe.

CONTINUIDAD
Se persiste la ubicación de curso y actividad activa, además de la vista activa entre curso, casos, repaso y dashboard.

EXPORTACIÓN / IMPORTACIÓN
Se añadió exportación JSON y restauración JSON. La importación valida versión y estructura antes de sobrescribir. No se incluyen datos innecesarios.

REINICIO
Se añadió reinicio explícito desde el dashboard. Reutiliza el modal accesible existente y explica qué se perderá antes de confirmar.

PERFORMANCE
Se añadió deduplicación por firma serializada: una escritura idéntica no vuelve a escribirse. Se registran en memoria tiempo de serialización, tamaño y número de escrituras omitidas/escritas para pruebas. No se optimizó nada adicional sin evidencia.

TESTS
- persistencia nueva
- recuperación
- migración v1→v2
- datos corruptos/incompletos
- navegación persistente
- exportación/importación
- reinicio
- deduplicación de escrituras
- regresión Fases 1–10

VALIDACIÓN MANUAL
Se cubrió mediante pruebas determinísticas el recorrido de recuperación. La validación visual interactiva de Chromium sigue limitada por el timeout headless del entorno, por lo que no se declara como PASS visual.

NO IMPLEMENTADO
No se añadieron funcionalidades pedagógicas nuevas, IA, ranking, gamificación, mastery, evaluación final ni rediseño.
