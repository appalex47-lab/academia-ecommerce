FUNCIONALIDADES
---------------
1. ¿Dónde estoy?
   - Progreso de lecciones completadas sobre las 8 lecciones de contenido.
   - Ejercicios resueltos sobre los 10 existentes.
   - Actividades pendientes.
   - No se calcula un score global de aprendizaje.

2. Conceptos
   - Conceptos con exposición/evidencia.
   - Conceptos practicados.
   - Conceptos con evidencia de dificultad.
   - Los nombres provienen del catálogo existente; no se inventan conceptos.

3. Pensamiento analítico
   - Comprender
   - Calcular
   - Interpretar
   - Diagnosticar
   - Hipótesis
   - Recomendación
   Se muestra como evidencia de práctica y no como calificación.

4. Siguiente paso
   Regla determinística:
   a) Si existe repaso disponible, se propone primero el repaso.
   b) Si no, se propone la siguiente actividad del curso no resuelta.
   c) Si las actividades están resueltas, se propone el siguiente caso disponible.
   d) Si todo está recorrido, se informa que puede volver a practicar o revisar casos.

5. Fortalezas
   - Utiliza evidencia real de ejercicios resueltos correctamente al primer intento.
   - Se muestra de forma descriptiva, sin ranking.

6. Áreas de práctica
   - Conceptos con evidencia de dificultad.
   - Tipos de error registrados cuando existen.
   - Se conserva lenguaje descriptivo.

7. Casos
   - Casos completados.
   - Casos disponibles.
   - Casos pendientes.

8. Repaso
   - Consume directamente generateReviewPlan() de Fase 8.
   - No crea un sistema de repaso paralelo.

FUENTES DE DATOS
----------------
Toda la información se deriva de:
- lessonStatus
- exerciseLearningState
- conceptEvidence / syncConceptEvidence()
- ANALYTICAL_CASES y caseLearningState
- generateReviewPlan() y reviewLearningState

REGLAS Y LIMITACIONES
---------------------
- No mastery score.
- No porcentaje artificial de dominio conceptual.
- No ranking.
- No comparación con otros alumnos.
- No gamificación.
- No IA, LLM ni predicciones.
- No evaluación final.
- El dashboard no altera el progreso por sí mismo.
- La navegación sigue siendo opcional y no bloquea el curso.

VALIDACIÓN MANUAL
-----------------
Se contemplaron los cinco escenarios exigidos por la especificación:
1. alumno sin progreso;
2. alumno con progreso parcial;
3. alumno con dificultades;
4. alumno con casos completados;
5. alumno con repasos pendientes.

La validación lógica automatizada cubre estos estados con datos controlados.
La validación visual/manual en Chromium headless permanece limitada por el entorno: en las fases anteriores el proceso headless termina por timeout sin producir un DOM utilizable. Esta limitación se conserva explícitamente y no se presenta como validación visual positiva.

RESPONSIVE Y ACCESIBILIDAD
--------------------------
- El dashboard usa grid/flex responsive y un breakpoint de 768px.
- Mantiene contraste y lenguaje visual existente.
- Usa encabezados y regiones semánticas.
- Los estados se expresan mediante texto y no solo color.
- El botón de navegación mantiene aria-expanded.
