MODELO IMPLEMENTADO
-------------------
1. CONCEPTO
Cada concepto existente mantiene un ID estable. El catálogo fue enriquecido con nombre, descripción, categoría y conceptos relacionados, sin duplicar conceptos.

2. EJERCICIO → CONCEPTO → NIVEL
Se reutiliza exerciseMetadata y normalizeExercise(). Cada ejercicio continúa declarando sus conceptos y su nivel cognitivo. Los ejercicios legacy sin metadata adicional siguen devolviendo una estructura segura con conceptos vacíos.

3. EVIDENCIA
La evidencia se agrega por pareja CONCEPTO + NIVEL COGNITIVO y conserva:
- exerciseIds;
- attempts;
- correct;
- firstAttemptCorrect;
- hintsUsed;
- solutionViewed;
- errorTypes;
- difficultEvidence;
- lastActivityAt;
- state.

La evidencia se deriva de los estados de ejercicios ya persistidos. Esto evita crear registros duplicados cuando se recalcula o se recarga la aplicación.

4. ESTADOS
Se implementan:
- not_started: no existe evidencia de interacción/lectura relevante;
- exposed: la lección asociada fue leída, pero todavía no hay práctica;
- practiced: hubo intentos sin evidencia de demostración correcta;
- demonstrated: existe una resolución correcta sin señales de dificultad acumulada;
- needs_review: existe evidencia de dificultad, como error, pista o solución revisada.

Estos estados son descriptivos. No son una escala numérica de mastery.

5. ERRORES Y PISTAS
La evidencia consume el errorHistory de Fase 3 y los datos de Fase 2:
- intentos;
- primer intento correcto;
- pistas utilizadas;
- solución vista;
- errores diagnosticados;
- resultado posterior.

Un ejercicio puede terminar correctamente y conservar needs_review si hubo señales de dificultad. Esto evita confundir “completado” con “dominado”.

6. ACUMULACIÓN
La misma pareja concepto/nivel puede recibir evidencia de varios ejercicios y lecciones. El historial de ejercicios no se sobrescribe; la evidencia agregada se reconstruye a partir de esos registros.

7. PERSISTENCIA
Se conserva la clave existente:
cursoAnalista.fase2.progress.v1

El objeto persistido mantiene version: 1 por compatibilidad y agrega conceptEvidence. Los datos anteriores de ejercicios y lecciones continúan siendo la fuente primaria de la evidencia; si conceptEvidence no existía, puede reconstruirse.

8. INTERFAZ
La Fase 4 ya mostraba la ruta cognitiva. Fase 5 añade dentro de esa misma zona una representación mínima de “Evidencia en esta lección”, mostrando concepto + nivel + estado descriptivo.

La interfaz no muestra porcentajes de dominio ni puntuaciones.

CORRECCIÓN DE COMPATIBILIDAD
----------------------------
Durante las pruebas se detectó que normalizeExercise() no heredaba los hints definidos en exerciseMetadata cuando el ejercicio no los tenía en su objeto base. Se corrigió para conservar los hints de metadata, lo que además permite que la evidencia de pistas de Fase 2 se registre de forma coherente.

VALIDACIÓN MANUAL
-----------------
Se intentó ejecutar la aplicación real mediante Chromium headless para recorrer la ruta solicitada:
lección → ejercicio → error → feedback → pista → nuevo intento → correcto → siguiente ejercicio → otra actividad del mismo concepto → comprobación del estado.

Resultado: NO APROBADA por limitación del entorno. Chromium quedó en timeout (20 s) y generó un DOM de 0 bytes. El stderr mostró errores de conexión a DBus. No se considera un resultado funcional positivo y no se marca como validación manual completada.

La lógica equivalente fue cubierta mediante tests automatizados con DOM/localStorage simulados.

REGRESIONES
-----------
No se detectaron regresiones en las pruebas de Fases 1–4. La persistencia continúa usando la misma clave. Se mantuvieron navegación, progreso de lectura, tolerancias numéricas, validaciones, ejercicios cualitativos, intentos, pistas, feedback, solución controlada y progresión cognitiva.
